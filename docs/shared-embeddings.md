# Shared embeddings

Requires Ez deployment schema 3. Embeddings remain off until `ez plugins shared-enable library embeddings`. The host manager creates/reuses `ez-shared-qmd-embeddings-v1` on its selected Docker daemon. Different Docker contexts/VMs are separate hosts. No networking between Library instances is added: only an IPC volume is mounted read-only at `/inference`. The worker alone mounts `/models`; it exposes no host port and has outbound network access for its first model download. Agents with Docker administration already have host-wide privileges; container labels are ownership/compatibility metadata, not an authentication mechanism against Docker administrators.

The shared worker calls pinned QMD 2.8.3's LlamaCpp embedding and tokenization methods. It downloads only embeddinggemma-300M-Q8_0 (about 300 MB), runs on CPU with one context, a hard 0.5-core Docker CPU quota and a 2 GiB container memory cap, and serializes a bounded queue of requests. Original text transits the worker for inference but is neither persisted nor logged by its HTTP interface. Original documents, SQLite indexes and vectors remain per agent. Model dimensions are checked at startup and on each client vector response.

A small pnpm patch adds an explicit `QMD_EMBED_MODULE` hook to the pinned QMD implementation. Library supplies only its packaged transport module through the subprocess environment whitelist. It handles four literal operations: embed, embedBatch, tokenize and detokenize. QMD retains prompting, chunking and indexing. Generation/reranking fail explicitly in this mode. This is a downstream patch, not a claimed upstream feature; a QMD upgrade must reapply/review the hook and repeat real indexing/query QA. Package and Docker locks include the patch hash.

`doctor` separates service readiness from private-index readiness. The resident supervisor refreshes enabled local files after readiness and every 60 seconds, under the existing writer lock. Transfer/index status remains separate for adopted folders. A failed shared worker never causes a local model download. Keyword retrieval remains available. Enabling does not erase existing vectors; the configured embedding model must match the pinned worker model.

Discovery validates ownership labels and the fingerprint of declared worker implementation files/dependencies. A unique Docker container name arbitrates concurrent creation. Compatible Library-only changes preserve attachment across managed updates. A worker implementation change blocks an attached Library upgrade before stopping clients. Coordinating replacement requires disabling all clients and explicitly managing the old host worker; automatic shared-worker upgrades and garbage collection are not provided in this version. The manager never deletes shared model volumes or stops a worker as a side effect of client uninstall. Uninstall/reinstall resets the client's opt-in; re-enable explicitly to reconnect.

Run `EZ_MANAGER_MODULE=/absolute/ez/src/plugins/manager.mjs node docker/shared-smoke.mjs` for actual two-agent manager QA. It creates its own uniquely named shared worker and volumes, downloads a model, verifies independent automatic indexes and semantic queries, restart, detach/uninstall, unavailable service and keyword search. It removes only its own QA containers and volumes. No user files or provider accounts are used.

The CPU quota is shared by all agents using the worker, not multiplied per agent. Half a core means at most half of one logical CPU over each scheduler period, leaving capacity even on single-core machines. Slower indexing is intentional. Model-operation transport allows up to 30 minutes of socket inactivity for throttled batches; health reads time out after five seconds. Change the reviewed descriptor `sharedServices.embeddings.cpus` to configure another bound (0.1–8); unlimited values are rejected. Existing legacy/manual embedding containers are unaffected until upgraded. Docker image builds are outside this runtime quota.
